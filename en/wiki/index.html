Installation

NanoRDS is a software RDS encoder for Linux and Windows. It generates a 57 kHz RDS subcarrier and a separate 19 kHz stereo pilot, with 192 kHz audio output. The same GNU Makefile is used on both systems.

Download

Download ready-built binaries from GitHub Releases, or clone the source code:

git clone https://github.com/barteqcz/NanoRDS

For a source build, install the development libraries for your operating system. Third-party libraries are not bundled with the source.

Linux (Debian / Ubuntu)

sudo apt update && sudo apt install build-essential pkg-config libsamplerate0-dev libao-dev
make
./build/linux/nanords --help

Other Linux distributions: install GNU Make, GCC, pkg-config, libao and libsamplerate from your package manager (including the development headers), then run make.

Windows (MSYS2 UCRT64)

Install MSYS2 and open the UCRT64 terminal, not the plain MSYS terminal. Install the required packages:

pacman -S --needed make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-pkgconf mingw-w64-ucrt-x86_64-libsamplerate mingw-w64-ucrt-x86_64-portaudio
make
./build/windows/nanords.exe --help

When running a locally built executable outside MSYS2, Windows must be able to find its runtime DLLs (for example, libsamplerate-0.dll and libportaudio.dll). Copy the required DLLs beside nanords.exe, or run it with the appropriate MSYS2 runtime directory in your PATH. Windows release archives bundle the runtime dependencies.

Audio output and build options

NanoRDS uses the default audio output device on both systems. Windows uses PortAudio WASAPI shared mode, so other applications can play simultaneously. There is no --device or --list-devices argument.

For Windows, set the default playback device to 192000 Hz in Sound → Playback → Properties → Advanced (you can open the Sound dialog with mmsys.cpl). NanoRDS rejects incompatible shared-mode mixer rates to avoid losing the 57 kHz RDS subcarrier. Other system sounds or audio enhancements can contaminate the signal sent to a transmitter.

The program outputs the FM multiplex signal on the left audio channel and silence on the right. It does not take music/audio input. The audio hardware and the complete playback chain must preserve the 192 kHz waveform.

The Makefile supports these commands:

make # compile
make clean # remove generated build files
make clean && make RBDS=1 # build with RBDS support

The RDS frequency is fixed at 57 kHz in source; there is no frequency flag or Makefile override. make install, make uninstall and make package are not provided by the current Makefile.

Command-line arguments

Use nanords --help (or nanords.exe --help on Windows) for the current argument list. Incorrect options or values also display help.

nanords --pi 1234 --ps SAMPLE --rt "Example RadioText" --pty 10 nanords --af a 87.7 98.0 88.6 nanords --af b 87.7 97.2 94.4 regional 105.2 94.1 nanords --file commands.txt

Common options: --pi HEX, --ps TEXT, --rt TEXT, --pty N, --ptyn TEXT, --ms 0|1, --tp 0|1, --di N, --ecc HEX, --lic HEX, --stereo N, --rds N, --af a ..., --af b ... and --file PATH. See file commands for dynamic updates and options such as TA, RT+ and CT.

AF selection is explicit: Method A uses --af a and Method B uses --af b. The old --af-method, --af-tuned, --af-regional, --fifo, and --device arguments are not supported.

Text-file control

On both Linux and Windows, --file reads a regular existing text file. No named pipe and no mkfifo are required. NanoRDS loads its contents on startup and checks for saved changes approximately every 250 ms.

Create a file called commands.txt and start NanoRDS:

./build/linux/nanords --file commands.txt

On Windows, run:

./build/windows/nanords.exe --file commands.txt

Edit and save the file while NanoRDS is running to apply your changes. Use one command per line. UTF-8 text, LF and CRLF line endings are supported. The file must exist at startup and can be up to 64 KiB.

Important: removing a line from the file does not automatically reverse its last setting. Send a new value, AF c to clear AF, or RESET to restore defaults. Each new AF a or AF b command replaces the previous AF list.

Text-file commands

Station identification and RadioText

PS — Programme Service name, up to 8 characters.

PS SAMPLE

RT — RadioText, up to 64 characters.

RT Example RadioText message

PI — 16-bit hexadecimal Programme Identification code. With an RBDS build, applicable North American callsigns may also be accepted.

PI 1234

PTY — Programme Type code (0–31). See PTY codes below. PTYN — extended programme-type name, up to 8 characters (use PTYN - to clear).

PTY 10
PTYN POP

Alternative frequencies (AF)

Method A sends an unpaired list of alternative frequencies. Use a on both interfaces:

AF a 87.7 98.0 88.6

Equivalent CLI option:

nanords --af a 87.7 98.0 88.6

Method B sends transmitter-specific frequency pairs. The first value is the frequency of your own transmitter; values after it are same-programme alternatives. Put regional before regional variants:

AF b 87.7 97.2 94.4 regional 105.2 94.1

Equivalent CLI option:

nanords --af b 87.7 97.2 94.4 regional 105.2 94.1

This example generates the same-programme pairs 87.7 → 97.2 and 87.7 → 94.4, and the regional pairs 105.2 → 87.7 and 94.1 → 87.7. The encoder determines pair order automatically. Frequencies are numbers such as 105.7, with no “MHz” suffix.

Method B supports up to 12 alternatives in one transmitter-specific list. Frequencies must be 87.6–107.9 in steps of 0.1 and must be distinct. If used, regional must be followed by at least one frequency.

To clear all alternative frequencies:

AF c

Only AF a, AF b, and AF c are valid control-file AF forms. The old AF s command has been removed.

RT+ and flags

RTPF sets RT+ flags: 0 = neither, 1 = toggle, 2 = running, 3 = both.

RTPF 2

RTP defines two RT+ text tags for the current RadioText. Format: type1,start1,length1,type2,start2,length2 (RT+ is sent in RDS group 11A).

RTP 4,0,6,1,9,8

MS sets music (1) or speech (0). TP indicates traffic programming, and TA signals a current traffic announcement. DI sets Decoder Identification information (0–15).

MS 1 TP 0 TA 0 DI 1

ECC is an extended country code (hexadecimal); LIC is a language code (hexadecimal). CT enables (1) or disables (0) the Clock Time group.

ECC E2 LIC 06 CT 1

STEREO controls the 19 kHz stereo-pilot level, and RDS controls the 57 kHz subcarrier level (0–100, including decimals). Set either to 0 to disable it.

STEREO 9 RDS 4.5

For calibrated levels, ensure your output volume and signal chain do not apply unwanted attenuation or processing.

RESET resets encoder settings to their defaults; it requires no argument.

RESET
